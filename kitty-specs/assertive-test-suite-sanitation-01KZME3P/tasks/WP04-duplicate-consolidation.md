# WP04 — Duplicate and Compatibility-Shim Consolidation

## Do First

Load `randy-reducer`. Read plan IC-04, research R1/R2/R6/R8, current path/compatibility ADRs, and WP01 duplicate fingerprints. Claim WP04 canonically. Syntax similarity is candidate evidence only.

## Objective

Consolidate exact and semantic duplicates, retaining the cheapest deepest live-path guard plus every unique platform, public import, or boundary oracle. Do not keep a slower wrapper test merely because it resides in a historical directory.

## T020 — Home/Path Suites

- Compare `tests/runtime/test_home_unit.py` with canonical kernel path tests function-by-function.
- Identify public import/shim behavior separately from underlying path semantics. A compatibility import that consumers still use is a distinct contract; a wrapper that reasserts the same output is not.
- Preserve `test_paths_unified_windows_root.py` cases that uniquely prove Windows drive/root and ASCII-safe semantics.
- Delete dominated cases/files and remove dead imports. Do not alter production behavior.

## T021 — Git-Ops Suites

- Compare legacy `test_git_ops.py` and `test_git_ops_unit.py` by production path, setup, and oracle.
- Prefer the suite exercising the current canonical entry point. Retain unique subprocess/error/platform behavior.
- For each proposed deletion, fault the claimed production seam or compare focused mutants; prove survivor fails equivalently.
- Consolidate helpers only if they reduce test-only indirection and stay within owned files.

## T022 — Dashboard Handler Suites

- Compare duplicate glossary handlers across `tests/specify_cli/dashboard` and `tests/test_dashboard`; repeat for lint tile handlers.
- Determine which reaches the live route/handler wiring rather than mocking the same current implementation.
- Retain unique HTTP/CLI shape or error boundaries; delete pure repetition and copied setup.
- Prefer one canonical directory aligned with current source ownership.

## T023 — Lane/Template Guards

- Audit `test_template_lane_guard.py` against other fingerprinted lane/template guards from the WP01 census.
- Within ownership, remove duplicated positive-shape checks. Preserve one negative current-authority invariant only if a plausible forbidden production change makes it fail.
- Do not keep exact token/name pinning as a substitute for behavior.
- If a matching test outside ownership is the survivor, this WP may delete its owned duplicate and cite the external survivor but must not edit that file.

## T024 — Causal and Mutation Proof

- Run focused `mutmut` only for source clusters actually claimed by deletions, or deterministic monkeypatch/fault injection where mutation configuration is disproportionate.
- Record non-equivalent mutants killed uniquely by each candidate and survivor.
- A candidate with no unique kill can consolidate; a unique boundary survives regardless of runtime.
- Import/collection failure does not count; Act must execute and intended oracle fail.

## T025 — Evidence/Validation

- `WP04.yaml` records family basis, members, production path, oracle, route roles, platform, cost evidence, survivor, and causal/overlap result.
- Expand parameters to node rows on any divergence.
- Run focused suites before/after and record node/time delta.
- `ruff` changed files and relevant platform-friendly tests.

## Definition of Done

- [ ] All owned duplicate groups adjudicated with named survivor/unique boundaries.
- [ ] Dominated cases removed; canonical live seams retained.
- [ ] Windows/public-import compatibility evidence prevents unsafe deletion.
- [ ] Focused causal/mutation comparison shows no lost unique kill.
- [ ] Ledger shard validates and focused suites pass.

## Reviewer Guidance

Independently compare production call paths, not just normalized bodies. Reject “same name” reasoning, mocked survivor replacing a live boundary, deletion of unique Windows/import cases, or mutation results that fail before Act.
